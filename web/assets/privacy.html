Privacy Policy

Deployment notice: This policy describes the default behavior of the NetDiag software. Before operating a public service, the operator must identify itself, provide a contact method, and specify applicable legal bases, logging practices, retention periods, recipients, and user rights. This template is not a substitute for an operator-specific policy.

Information processed

NetDiag processes network connection information to display diagnostics and run requested speed tests. The web server can see the IP address of its directly connected peer, basic HTTP request information, and server-side TCP connection metrics. A reverse proxy may observe additional connection information under its own configuration.

Download tests transfer generated data to the browser. Upload tests send generated test data to the server, which reads and discards it without writing the payload to an application database. Measurement results are displayed in the browser.

Automatic diagnostics and third parties

When the homepage opens, the browser requests lightweight diagnostics. If independent IPv4 and IPv6 probe origins are configured, the browser also requests those operator-provided endpoints to measure address-family connectivity and approximate HTTP response time. Each endpoint can observe the directly connected peer IP address. If WebRTC is available, it also attempts to contact configured public STUN servers run by third parties. Those providers may receive the browser's public network address and mapped UDP port and handle this information under their own policies. NetDiag does not send WebRTC candidates to its application server in the default configuration.

Browser settings or network restrictions can prevent STUN probes. The bandwidth test does not start until you select Start test.

Cookies, advertising, and analytics

The default application does not set cookies, use local storage for tracking, include advertising, or load analytics scripts. Operators who add these features must update this policy and implement any required controls.

Local ASN lookup

When enabled, the site looks up the directly connected peer IP address in a locally installed MaxMind GeoLite2 ASN database to display an autonomous system number and organization name. Lookup requests are not sent to MaxMind. Database files are downloaded and updated separately by the site operator.

Storage and retention

The starter application does not provide user accounts or a persistent measurement database. Infrastructure such as a web proxy, hosting platform, or firewall may keep access and security logs. Log contents and retention periods depend on the operator's deployment and must be disclosed by that operator.

Contact and updates

The service operator must publish a contact method for privacy inquiries and explain how this policy is updated before making the service publicly available.
